# 测试驱动开发

## 核心规则

新生产代码应先有测试或可执行验证用例。

## 流程

1. 写一个最小测试，表达期望行为。
2. 运行测试，确认它因为目标行为缺失而失败。
3. 写最小实现让测试通过。
4. 重新运行测试。
5. 通过后再清理代码。

## 适用重点

- 协议 parser。
- 云端 API 校验。
- 数据模型迁移。
- 关键业务逻辑。
- bugfix 回归测试。

## 无法自动测试时

记录原因，并提供可手动执行的验证命令或 checklist。
