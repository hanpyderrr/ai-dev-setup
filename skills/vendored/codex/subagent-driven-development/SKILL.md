# 子 Agent 驱动开发

## 使用前提

- 用户明确要求使用 agent/多 agent/并行 agent。
- 子任务之间写入范围清晰且尽量不重叠。
- 每个 agent 有明确输入、输出、验证方式。

## 分工模板

每个 agent 指令应包含：

- 项目根目录。
- 负责文件范围。
- 禁止修改的范围。
- 具体任务。
- 验证命令。
- 最终回复格式。

## 集成规则

1. 主 agent 保持协调，不重复子 agent 的工作。
2. 子 agent 返回后先看 diff，再看结果说明。
3. 做两轮审查：
   - 需求符合性。
   - 代码质量、风险、测试。
4. 有冲突时优先保护用户已有改动。
5. 记录最终结果到项目进度文件。

## 注意

Codex 中只能在用户明确要求时使用子 agent；不要因为任务复杂就自行派生 agent。
